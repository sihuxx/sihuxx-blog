
| 명령어        | 비유         | 동작                                      |
| ---------- | ---------- | --------------------------------------- |
| `reset`    | 시간을 되감는 것  | 지정한 커밋 시점으로 돌아가고, 그 이후 커밋 기록은 삭제        |
| `revert`   | 과거를 청산하는 것 | 특정 커밋의 작업을 거꾸로 진행하는 새 커밋 생성, 기록은 그대로 보존 |
| `checkout` | 과거로 돌아가는 것 | 기록은 건드리지 않고 과거 시점을 둘러보는 용도              |

## 1. reset

```bash
git reset --hard 커밋해시
```

- 지정한 커밋 시점으로 파일과 기록 모두 되돌림
- 커밋 해시를 붙이지 않으면 마지막 커밋 상태로 모든 파일이 되돌려짐
- 주의: `--hard`는 저장하지 않은 변경사항까지 삭제되어 복구 불가

## 2. revert

```bash
git revert 커밋해시
```

- 특정 커밋의 작업을 거꾸로 진행하는 **새로운 커밋** 생성
- 기존 기록이 남아서 이미 공유한 저장소(push 이후)에서 안전한 방식

**파일 충돌 시**

1. 충돌 파일 해결 (삭제할 파일이면 `git rm 파일명`, 수정한 파일이면 `git add 파일명`)
2. `git revert --continue`

## 3. checkout

```bash
git checkout 커밋해시   # 과거 시점으로 이동
git switch main         # 원래 브랜치로 복귀
```

- 과거 시점을 둘러보는 용도 (이 상태를 detached HEAD라고 부름)
- 이 상태에서 커밋하면 기록이 브랜치에 연결되지 않아서 보통 둘러보기만 하고 복귀

## 4. 정리

- 내 로컬에서 완전히 없던 일로 만들고 싶을 때 → `reset`
- 이미 push한 커밋을 취소하고 싶을 때 → `revert`
- 그냥 과거 코드를 확인하고 싶을 때 → `checkout`
