## 1. 자바란?

**자바의 특징**
- 운영체제에 독립적인 언어
![[Pasted image 20261007194746.png]]
```
Hello.java → (javac 컴파일) → Hello.class(바이트코드) → (JVM 실행) → 각 OS에서 동작
```
- 객체 지향 언어 (Object Oriented Programming, OOP)
- 함수형 프로그래밍 지원
- 자동 메모리 관리

**자바를 사용하는 이유**
- 운영체제 독립성
- 객체 지향
- 자동 메모리 관리
- 풍부한 라이브러리 및 생태계
- 높은 안정성 및 유지보수성
- 멀티스레드 프로그래밍 지원

## 2. JVM, JRE, JDK
![[Pasted image 20261007194721.png]]
포함 관계: JDK ⊃ JRE ⊃ JVM

**JVM** (Java Virtual Machine)
> 자바 소스 코드 (.java)가 컴파일된 결과물인 바이트 코드 (.class)를 읽어들여 OS가 이해할 수 있는 기계로 변환하고 실행시키는 역할

- 운영체제 독립성 보장 (운영체제마다 맞는 기계어로 번역)
- 메모리 관리 (가비지 콜렉션)

**JRE** (Java Runtime Environment)
> 말 그대로 런타임 환경, 자바 프로그램이 돌아가는데 꼭 필요한 뼈대

- 구성요소: JRE = JVM + Java Class Libraries (표준 라이브러리)

**JDK** (Java development Kit)
> 프로그램을 실행하는 환경 (JRE)에 더해, 소스 코드를 작성, 컴파일, 디버깅 할 수 있는 도구들을 제공

- 구성요소: JDK = JRE + Development Tools (개발 도구)
- 주요 개발 도구
	- javac (Java Compiler): 사람용 자바 소스 코드(.java)를 JVM이 이해할 수 있는 바이트 코드 (.class)로 변환
	- java (Java Launcher): 작성된 바이트 코드 실행
	- jdb (Java Debugger): 실행 중인 프로그램의 오류를 찾고 수정하는 디버깅 도구
	- jar (Java Archive): 관련된 클래스 파일들을 하나의 압축 파일 (.jar)로 묶어주는 도구

| 이름      | 뜻                                                | 비유             |
| ------- | ------------------------------------------------ | -------------- |
| **JVM** | Java Virtual Machine, 바이트코드를 실행하는 가상 컴퓨터         | 통역사            |
| **JRE** | Java Runtime Environment, JVM + 실행에 필요한 기본 라이브러리 | 통역사 + 사전       |
| **JDK** | Java Development Kit, JRE + 개발 도구 (`javac` 등)    | 통역사 + 사전 + 번역가 |

## 3. 가비지 컬렉션
- 힙 영역에서 더 이상 참조되지 않는 객체를 자동으로 정리하는 기능
- 가비지 = 어떤 변수도 주소를 갖고 있지 않은 객체
```java
String s = new String("사과");  // 힙에 "사과" 생성, s가 주소를 들고 있음
s = new String("바나나");       // s가 "바나나" 주소로 바뀜
// 이제 "사과"는 아무도 안 가리킴 → 쓰레기!
```
- 참조가 남아 있으면 안 쓰는 객체라도 정리되지 않음 -> 메모리 누수 원인
- 판단 기준: GC Root (스택의 지역 변수, static 변수 등)에서 참조를 따라가 닿을 수 있는지 여부

## 4. 객체 지향 프로그래밍이란

> 객체를 중심으로 프로그램을 설계하고 만드는 방식

**핵심 개념**
- **객체**: 상태를 나타내는 변수 (속성)과 행동을 나타내는 함수 (메소드)의 묶음
- **클래스**: 객체를 만들기 위한 설계도 또는 틀

**주요 특징**
- **캡슐화**: 데이터와 코드를 하나로 묶고 내부 세부 사항을 숨기는 것
- **상속**: 기존 클래스의 속성과 기능을 새로운 클래스가 물려받아 재사용하는 것
- **다형성**: 하나의 이름이나 형태가 상황에 따라서 다르게 동작하는 것
- **추상화**: 공통된 특징을 추출하여 불필요한 세부 사항 제거

**장단점**
- **장점**: 코드 재사용이 쉬움, 유지보수 편리, 대규모 프로젝트에 알맞음
- **단점**: 설계에 시간이 오래 걸림, 실행 속도 다소 느림

## 5. 하이브리드 언어

> 컴파일 언어의 빠른 속도와 인터프리터 언어의 유연성 (플랫폼 독립성)을 모두 가진 프로그래밍 언어

- 컴파일 언어와 인터프리트 언어를 혼합한 형태로 두 가지의 장점을 갖춤
- 인터프리터에 비해 빠르고, 소스 코드 노출의 우려가 적음
- 운영체제에 종속되지 않음
- 고급 언어로 작성된 프로그램을 쉽게 해석 할 수 있도록 중간 코드 형태로 번역
- 번역된 중간 코드 형태의 프로그램을 해석하여 실행

![[Pasted image 20261007200751.png]]
**컴파일러** (Compiler) ^58dc63
> 전체 소스 코드를 한번에 읽고 분석하여 기계로 된 실행 파일 생성

- **번역 단위**: 전체 소스 코드
- **장점**: 실행 속도 빠름, 실행 전 전체 오류 미리 확인 가능
- **단점**: 코드를 수정할 때마다 전체를 다시 컴파일해야 하므로 초기 준비 시간 김
- **자바 컴파일러(javac)** 가 사람이 작성한 소스코드 (.java)를 컴퓨터가 이해할 수 있는 중간 단계인 바이트 코드 (.class)로 변환하는 **컴파일러 역할 수행**

**인터프리터** (Interpreter) ^9a2a75
> 소스 코드를 한 줄씩 (또는 행 단위로) 읽어가며 즉시 실행

- **번역 단위**: 한 줄 (행)씩
- **장점**: 별도의 실행 파일을 만드는 빌드 과정이 없어 코드 수정 후 바로 결과 확인 가능
- **단점**: 실행할 때마다 매번 해석 과정 거치므로 전체 실행 속도 느림
- 자바 가상 머신 (JVM)이 바이트 코드를 받아 실시간으로 읽고 실행하는 **인터프리터 역할 수행**하여 각 운영체제에 맞는 기계어로 번역
