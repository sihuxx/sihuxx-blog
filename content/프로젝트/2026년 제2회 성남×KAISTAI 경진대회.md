## 1. 프로젝트 소개

안심길은 **가장 빠른 길이 아니라 가장 덜 힘든 길**을 찾아 주는, 언덕 동네 어르신을 위한 도보 길안내 웹앱이다.

성남 원도심(수정구·중원구)은 1970년대 광주대단지 이주 정착지로 산비탈에 급하게 만들어진 동네다. 그래서 지금도 언덕과 계단, 좁은 골목, 인도 없는 길이 많다. 그런데 지도 앱의 도보 길찾기는 "가장 빠른 길"이 기준이라 계단이 197단이나 있는 길도 그대로 추천한다. **"가까운 길이 편한 길은 아니다"**라는 생각에서 이 프로젝트를 시작했다.

|항목|내용|
|---|---|
|서비스 지역|성남시 중원구 은행동 (3개 구역)|
|주요 대상|고령 보행자|
|서비스 형태|모바일 웹앱(PWA), QR로 바로 실행|
|차별점|직접 걸어서 조사한 보행 데이터 활용|

예를 들어 은행근린공원 서쪽입구에서 구현진약국까지 가장 짧은 길에는 **계단 197단**이 있다. 안심길은 **같은 12분** 안에 계단 없는 길로 안내한다.

길을 찾을 때는 계단·오르막·신호 없는 횡단보도·인도 없는 길을 고려해 덜 힘든 길을 추천하고, 최대 3개 경로를 시간·거리·계단 수·높이 변화로 비교할 수 있게 했다. 안내는 "50m 앞"이 아니라 "유할인마트 정류장 앞에서 오른쪽으로 도세요"처럼 장소 이름으로 하고, 단계마다 음성으로 읽어 준다. 그 밖에 이런 기능이 있다.

- 말로 목적지 찾기: "구현진약국 가줘"라고 말하면 바로 길을 찾음
- AI 사진 제보: AI가 사진 속 계단을 먼저 찾고, 사용자가 확인한 내용만 길찾기에 반영함
- 맞춤 설정: 계단 회피, 돌아가는 정도(1.3배 / 2배), 글자 크기 5단계

## 2. 프로젝트 과정

**팀 구성** — 정서윤 기획·앱 디자인 / 김다은 발표·발표자료 제작 / 박시후 팀 대표·앱 개발·AI 학습

**기간** — 예선 계획서 제출 → 예선 통과 → 약 한 달간 본선(10.24) 준비

```
주제 선정 → 예선 계획서 → 예선 통과 → 현장조사 → 데이터 구축
→ 경로 알고리즘 → 앱 개발 → AI 학습(1차·2차) → AI 앱 탑재
→ 테스트 → 시연 영상 · 발표자료 → 본선 발표
```

### 2-1. 기획

**주제 변경** — 도보 여행 코스 추천 + 미션·포인트 앱에서, 성남 원도심 산비탈 이동 불편을 해결하는 고령자 보행경로 안내로 전환

**근거 조사** — 성남시 연령별 인구 동 단위 분석으로 은행2동 65세 이상 비율 증가 확인, 고령친화도시 정책·보행안전 기본계획에서 공공적 근거 확보

**주민 설문·인터뷰** — 가장 많은 불편은 언덕·계단과 좁은 길, 인터뷰 내용을 기능 설계에 반영

|인터뷰 내용|반영한 기능|
|---|---|
|좁은 길·불법주차가 더 위험하다|인도 없는 길에 더 높은 점수|
|건물 기준으로 알려주면 쉽다|장소 이름 안내, 꺾는 곳 줄이기|
|1.3배까지는 돌아가도 괜찮다|돌아가는 정도 설정 (1.3배 / 2배)|

### 2-2. 현장조사

**조사 이유** — 성남시 공공데이터의 은행동 일대 장애물·보행자 전용도로 정보 0건, 지도에 계단 수·경사·신호등 고장 정보 없음

**현장 조사** — 10월 4일, 은행동 3개 구역 **31개 구간 · 약 3km** 도보 조사, 사진 **76장** 촬영

**기록 항목** — 폰 경사계로 구간별 경사 2~4회 측정, 계단 수, 인도 유무, 횡단보도·신호등 상태, 노면, 조명

**발견한 위험 요소** — 나무 계단 197단, 무지개 계단 51단, 고장 난 신호등 3곳, 인도 없는 좁은 차길 3곳

### 2-3. 디자인

**디자인 원칙** — 흰 배경 + 초록 포인트 색 하나, 큰 글씨·큰 버튼, 색과 함께 아이콘·선 모양·글자로 구분

**색 결정** — 초록 → 여러 색 시안 → 네이비 → 최종 초록으로 복귀

**안내 방식 변경** — 자동으로 넘어가는 방식에서, 걷는 속도에 맞춰 사용자가 한 단계씩 넘기는 방식으로 변경

### 2-4. 개발

**길 데이터 제작** — 갈림길은 점, 길은 선으로 잇는 그래프를 Python으로 구성. OpenStreetMap 골목길 565개를 추가해 보았으나 계단·경사를 모르는 길의 위험 때문에 **직접 확인한 길만** 사용. 길 75개, 장소 35곳, 이어진 장소 쌍 182개

**덜 힘든 길 계산** — 길마다 힘든 정도 점수를 매기고 **다익스트라 알고리즘**으로 점수 합이 가장 작은 길 탐색, 경사 부담은 **Tobler 보행속도 함수**로 계산

**꺾는 곳 줄이기** — "지점 + 들어온 길"을 한 상태로 보는 탐색으로 꺾는 횟수 경로당 2.3회 → 1.5회

**예상 시간 계산** — 어르신 걸음(분당 50m) + 경사·계단·신호 대기 반영

**앱 제작** — 프레임워크 없이 HTML · CSS · JavaScript로 구현, 화면을 그리는 렌더러 직접 제작, PWA로 홈 화면 설치·오프라인 실행, Netlify 배포 + QR 접속

**AI 1차 학습** — 사진을 픽셀 단위로 계단·인도·차도로 나누는 **DeepLabV3+** 모델을 AI Hub 「인도보행 영상」으로 학습. 계단 사진 3.9%뿐인 데다 계단 표시 상당수가 맨홀·보도블록이라, 372장을 직접 검수해 진짜 계단 194장만 사용

**AI 2차 재학습** — 1차 모델이 현장 사진에서 하늘을 도로로 칠하는 문제 발견, 원인 4가지 분석 후 수정

- 배경 사진 부족 → 계단 없는 사진 1,200장 추가
- 세로 사진이 찌그러져 들어감 → 사진 비율 유지
- 비슷한 장면으로 시험해 점수 부풀림 → 촬영 폴더 단위로 학습·시험 분리
- 인도·골목 미구분 → 인도 / 골목 / 차도 분리

**2차 결과** — 하늘·건물을 바닥으로 칠하는 비율 **9.9% → 3.5%**, 현장 25개 구간 중 **23개** 계단 유무 일치

**AI 앱 탑재** — 학습 모델을 **ONNX로 변환** + **8비트 압축**(107MB → 27MB, 변환 전후 일치율 98.6%), onnxruntime-web으로 휴대폰 브라우저 안에서 실행. 서버 없음, 사진 외부 전송 없음

**사진 제보 기능** — AI가 먼저 계단을 판단하고 사용자가 확인한 것만 반영하는 구조. AI가 틀려도 잘못된 길로 안내되지 않음

**테스트·버그 수정** — Playwright로 첫 화면부터 사진 제보, 다시 길찾기까지 자동 확인. 제보한 작은 계단 때문에 197단 계단 길로 안내되던 버그, 아이폰 파란 글자 문제 수정

|영역|기술|
|---|---|
|앱|HTML · CSS · JavaScript, PWA|
|경로|Dijkstra, Tobler 보행속도 함수|
|지도 · 데이터|OpenStreetMap, 성남시 공공데이터, Python|
|AI|PyTorch, Google Colab, DeepLabV3+, ONNX, onnxruntime-web|
|음성|Web Speech API|
|테스트 · 배포|Playwright, Netlify|

### 2-5. 발표

**발표 구성** — 5분 안에 문제, 데이터, AI, 시연, 기대 효과를 담는 흐름 설계

**시연 영상 제작** — 제보 후 경로가 바뀌는 장면이 확실히 나오도록 코드로 전체 경로를 계산해 시연 경로 선정

**Q&A 준비** — 기능명세서, 개발 과정 문서, Q&A 대비 자료 작성 후 예상 질문으로 답변 연습

## 3. KPT 회고

### Keep (잘한 점)

**직접 발로 뛰어 데이터를 만들었다.** 공공데이터에 없는 계단 수, 경사, 고장 난 신호등을 직접 조사했고, 이게 서비스의 가장 큰 차별점이 됐다.

**사용자의 말을 설계에 그대로 반영했다.** 인터뷰 한 줄이 점수 계산과 안내 문장을 바꿨다.

**AI 오류의 원인을 끝까지 파고들었다.** 현장에서 틀린 결과를 보고 원인 네 가지를 찾아 직접 고쳤고, 그 과정에서 가장 많이 배웠다.

**AI를 안전하게 쓰는 구조를 만들었다.** AI 혼자 결정하지 않고 사람이 확인한 것만 반영하도록 했다. 같은 이유로 GPS 출발지, 손잡이 조건, 확인 안 된 길처럼 정확하지 않은 기능은 과감히 뺐다.

### Problem (개선할 점)

**어르신 사용 테스트를 하지 못했다.** 인터뷰는 했지만 실제로 앱을 써 보시게 하지는 못했다.

**AI와 데이터의 한계가 남았다.** 학습 사진(서울 보도블록)과 은행동 환경이 달라 인도 판정은 앱에 쓰지 못했다. 서비스 범위도 은행동 3개 구역 안으로 좁고, 제보는 서버 없이 각 휴대폰에만 저장된다.

**일정 관리가 아쉬웠다.** 마감이 가까워서 AI 재학습과 기능 추가를 함께 하느라 문서와 발표자료가 여러 번 바뀌었고, 미조사 구간 촬영 계획도 실행하지 못했다.

### Try (다음에 시도할 점)

**사용 테스트를 일정 초반에 넣겠다.** 기능을 다 만든 뒤가 아니라 중간중간 실제 사용자에게 보여 주고 고쳐 나갈 것이다.

**학습 전에 데이터부터 의심하겠다.** 이번에 정답 데이터 절반이 틀렸던 경험을 살려 검수부터 하고, 우리 동네 사진으로 추가 학습해 인도 판정까지 쓸 수 있게 만들고 싶다.

**서비스를 넓히겠다.** 서버를 연결해 주민 제보를 모으고, 실시간 GPS 안내를 더해 성남 원도심 다른 동으로 확장하는 것이 다음 목표다.

**일정에 여유를 두겠다.** 마감 직전에 큰 변경이 몰리지 않도록 단계별 목표 날짜를 미리 정할 것이다.
